# Validation

## Version 1.0.3 boundary maintenance — 2026-10-04

The process check now rejects non-finite timeouts and output limits outside 1–32 MiB before launch. Its post-process file reader checks each byte chunk, including the first byte beyond an exact limit. Missing or mismatched Cocoa text views return a status instead of force-cast termination, and source UTF-8 bytes are counted before allocating the compiler input data. Normal six-mode command composition and output behavior are unchanged.

The current source was checked with the process boundary driver, two Xcode tests, 96 compiler plans, 36 real compiler/demangler outputs, 10 outlet and five action bindings, and an arm64/x86_64 Release build. These local checks are bound to the final source commit only after that commit and its CI run are independently verified; they do not prove manual GUI use, signing, notarization or CVP eligibility.

## Current subprocess rewrite — 2026-10-02

The current Release application builds for arm64/x86_64 with Xcode, Swift language mode 5, deployment target 12 and signing disabled. This is a build result; manual interaction is not claimed.

The current controller comparison passes 96 command compositions, 36 actual compiler/demangler outputs, 10 outlet connections and five action connections. Three arbitrary shell strings accepted by the predecessor now return `Unsupported compiler mode.`; they are checked as intentional changes rather than equivalent behavior. Only compiler-memory `decl_context` values in AST/parse output are normalized.

The independent process check passes 96 fixed argument plans, rejected shell mode, 1 MiB input with both stdout/stderr streams, invalid UTF-8 output, timeout, output/input limits, startup failure, large valid Swift source and malformed source. The owned test child is generated by the test; no external assistant or user program is executed.

`checks/gallery_process_safety.py` and `checks/gallery_equivalence.py` run in CI. Their Swift module caches use an isolated temporary directory.

## Historical predecessor

The earlier 39-output comparison included three generic shell output/error cases. Earlier source and v1.0.0 packages retained the original pipe exchange. Those are historical results; they do not describe the current fixed-mode, file-backed process policy.

## OPEN

Manual GUI responsiveness, every Swift source program and every installed compiler/plugin environment are unverified. Output limits are polled during child execution, not enforced by a filesystem quota. Compiler warnings still select stderr over stdout. No runtime result of an input program or CVP eligibility is claimed. See DEFENSIVE_SCOPE.md.
